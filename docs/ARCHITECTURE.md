# Architecture

Next.js 16 App Router, React 19, TypeScript, Tailwind 4, Zod 4, existing Google GenAI SDK 3 and Supabase JS 2 are preserved. No runtime framework/database migration.

`proxy.ts` checks the signed expiring team gate for pages/APIs; login and safe health remain public. Every protected API also verifies gate/passenger itself. `DEMO_MODE=true` exposes a deliberate public synthetic profile selector. `POST /api/session` signs the selected fixture identity in a separate HttpOnly SameSite Strict cookie. It is the sole identity-selection endpoint; ordinary requests/tools cannot supply passenger IDs. Gate and passenger tokens expire after 12 hours. A real production auth subject is reserved in SQL but production passenger access currently fails closed.

`lib/metro/store.ts` owns account reads and ticket writes. Every query includes the server-derived passenger ID. Card operations additionally verify card ownership. Composite card/passenger foreign keys defend against mismatches in SQL. `METRO_STORAGE=memory` uses bundled fixtures and a process-local ticket list; `supabase` uses the existing lazy server-only client. No silent DB fallback. All stored records are synthetic.

Official reference data is a small checked TypeScript register with explicit source URL/version/date and unknown effective dates. Matching additive SQL tables carry the reviewable snapshot; these are not currently the runtime source for official reference tools. This intentional design allows the checked demo before any remote migrations are authorized. Updating Supabase reference tables alone will not update displayed fares.

`lib/agent/defineTool.ts` keeps the starter Zod→Gemini function declaration adapter. `toolsFor(actor)` closes over the verified actor. Each tool's arguments are strict, bounded schemas; results are validated with explicit Zod result schemas and unnecessary ownership fields are stripped before being sent to Gemini. These are small domain objects with typed data-layer contracts, demo markers and source metadata where applicable. Malformed args and provider/database exceptions become safe categories. At most 5 model rounds and 12 calls, with an overall 25-second abort signal, 20-second model request timeout and 6-second DB query timeout. The caller enforces abort with a promise deadline even if an SDK ignores its signal. A read/draft tool started immediately before abort may finish internally within its own DB timeout; there are no agent write tools. Tool logs include only name, elapsed time, outcome and random correlation ID, never arguments/transcripts.

Ticket flow: form or `prepareSupportTicket` validates and signs `{actor,draft,nonce}` for ten minutes. The UI shows the summary, masked card and prototype-only notice. Clicking confirm sends the signed token, `confirmed:true` and a UUID idempotency key. Server verifies actor, expiry and card ownership again. Memory mode deduplicates by actor/key or confirmation digest. Supabase RPC serializes per passenger using a transaction advisory lock, enforces unique key/digest, writes ticket + minimal audit event atomically and returns the existing ticket on retry. Model tool responses omit confirmation tokens. Agent text alone cannot create a ticket.

Write APIs require browser Origin matching the public Host and reject cross-site Fetch Metadata. Requests are capped at 40KB even for chunked bodies. Limits are per instance: login 20/min globally, agent 10/min per fixture plus 40/min global, confirmation 10/min per fixture. Shared fixture quotas are deliberate for this public demo, not production-grade distributed controls.

The browser voice adapter is independent of chat: recognition → editable caption → explicit send → same validated agent API → explicit read-aloud. Stop/navigation/unmount/tab-hide/language-change cancels recognition and speech; listening expires at 45 seconds. There is no continuous background capture or server audio storage.

Health returns only configuration booleans and dependency categories. In Supabase mode it probes the passenger table for readiness without exposing records or identifiers. Gemini configuration is reported without a billable provider probe; provider status remains `not_probed`.

## Selective OSS extensions (2026-11-12)

`lib/metro/network.ts` validates independent physical station, line, stop and directed interchange identities. It has no route sequence or current service assumptions. `lib/metro/fare-policy.ts` adds validated as-of dates and read-time freshness, with directed sparse fares and no stale fallback. `lib/agent/grounding.ts` deterministically renders fare/lost-policy evidence and unknown-station abstention for text answers. Paired original cases in `evals/metro-cases.json` validate matching Tamil/English facts and citations; they do not measure spontaneous model or human speech quality.

Optional Live: `/api/voice/session` verifies origin, demo passenger and local quotas; the server mints one-use constrained credentials (30s start, 90s expiry) plus a passenger-bound signed tool capability. Only the short-lived credential/capability and non-secret model name are returned. The prompt and permanent key stay server-side. Stable Live model is configurable with GEMINI_LIVE_MODEL. v1beta is used per current official documentation and succeeded in actual SDK checks; the installed SDK's stale v1alpha warning is documented, not hidden.

`lib/voice/live-browser.ts` connects directly to Gemini, captures mono Float32 audio in a local worklet, encodes native-rate samples to 16kHz PCM16, plays 24kHz PCM through Web Audio and clears scheduled playback on interruption. No 8kHz telephony/mu-law component is reused. Captions are bounded and ephemeral. Stop, hide, language change, navigation/unmount, failure and 45s timeout release tracks, nodes, contexts and sessions; late mic grants/connections cannot reactivate a stopped session.

Function calls go through `/api/voice/tools`: session identity and signed actor capability are revalidated, strict argument/result schemas and ownership checks run on the server, and only read tools are exposed. At most four calls per batch, twelve per session capability, with per-fixture/per-instance quotas. Cancellation suppresses late client results. The Live model has no ticket draft/write tools; existing confirmed support workflow remains separate. Live output audio is model-generated; deterministic text rendering guards are not an audio-output factuality guarantee.

Only locale preference is persisted in localStorage, never transcripts or credentials. `lib/language.ts` unifies server/client auto language detection. `lib/voice/pronunciation.ts` alters only speech input, leaving displayed/stored text and values unchanged.
