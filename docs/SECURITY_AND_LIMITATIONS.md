# Security and limitations

- Permanent Gemini and Supabase secrets remain server-only. The browser receives no permanent key. No actual environment file is printed or committed.
- A strong team passcode both gates access and signs domain-separated expiring HMAC tokens. Rotating it invalidates all sessions/drafts. It is not passenger authentication. Anyone with demo access can intentionally select any public synthetic fixture; no real personal records belong here.
- Production mode fails closed without real authentication. `DEMO_MODE=true` is mandatory for this prototype. Do not connect genuine passenger data.
- All write routes validate Zod, same-origin, session, ownership, body size and bounded local rate limits. Supabase service-role bypasses RLS; server checks are mandatory. Tables grant no access to anon/authenticated; only the server can execute ticket RPC. Distributed rate limiting is not shipped.
- Only an explicit confirmation request writes a prototype ticket. A ten-minute signed draft binds actor and contents; key and confirmation-digest uniqueness prevent retry/replay duplicates. Drafts are not submitted to CMRL. Idempotent replay after draft expiry returns an expiry error; existing tickets remain visible through the list.
- Memory mode is temporary and per process: restarts lose tickets; different Vercel instances may have different lists. Use Supabase after approved migration for a persistent judge demo. Supabase errors are surfaced safely, never silently hidden by memory fallback.
- SQL is additive, no drop/truncate/reset; legacy SQL is inactive. Local migration tests are not proof of hosted Supabase/PostgREST configuration. Remote migration and hosted smoke tests still require approval.
- No payment, actual recharge, refund, transfer, card block, real card reading, issuer integration or CMRL complaint submission exists.
- No raw audio or complete chat history is persisted by the application. Submitted text goes to Gemini; browser speech services may process audio remotely. Support description is retained as operational ticket data; users should enter synthetic details only. For public production use, define retention/deletion and provider agreements first.
- Tool logs exclude inputs/results and include safe name/timing/outcome/correlation metadata. Durable ticket audit stores only actor, event, ticket ID and time. Memory mode has no durable audit log.
- Official data covers seven named stations and four directed fare pairs, with standard/discounted amounts separately sourced. No complete matrix, current full network, train schedules or route calculations. Do not infer operating status from fare tables. Effective date and discount eligibility may need checking with CMRL.
- IT/AFC recharge guidance contains historical information and is labelled partial. Lost-card guidance reflects the dated official 7 January 2026 notice. No recovery/blocking promises.
- Browser recognition/synthesis support varies. Tamil recognition, Tanglish detection and Tamil installed voices need device testing; optional Gemini Live is implemented and disabled by default. SDK/tool probes succeeded in Tamil/English, but actual microphone capture and speaker quality still need device checks. Auto recognition starts in English, so explicitly choose Tamil for a first Tamil voice query. Text remains usable after voice failures.
- Tamil UI translations are a draft and require native-speaker review. They are not official CMRL translations.
- UI contains responsive breakpoints, semantic labels, live regions, focus rings and reduced-motion support. Actual visual, keyboard/screen-reader and microphone QA remain manual where automation is unavailable.
- No deployment performed. Do not deploy to production until approved.

- Live uses one-use constrained 90-second credentials; no permanent key reaches the browser. A signed actor-bound capability is required for all server read tools. Live cannot draft/create tickets. Captures stop after 45 seconds. SDK/caption/tool checks do not prove real microphone behavior or a universal audio factuality guarantee.
- Community CMRL GTFS is quarantined: expired 2021 calendar, stale fare source, incomplete current network and uncleared mirrored dataset rights. Metadata inspection is not permission to redistribute or operate a live schedule. Sarvam source was not copied because the checked tree lacks its referenced LICENSE. See OSS_REUSE_REPORT.md.
- Fare records expire for this prototype after a local 30-day review window; this is not a CMRL official validity period. Unknown effective dates stay unknown. Current/historical/future requests may abstain; do not change verification dates to avoid that protection.
- The SDK 3 emits an older warning that ephemeral tokens are v1alpha-only; current Google documentation and actual v1beta English/Tamil checks succeeded. Keep this compatibility caveat in the deployment review.
