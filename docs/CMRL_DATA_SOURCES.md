## Extraction and maintenance

Fetched official fare landing HTML and located its two linked PDF URLs, then inspected the extracted station headings and numeric rows in both PDFs. Only the first adjacent pair and Airport–Guindy pair are used, with reverse rows checked separately. No fare was computed from distance or discounts. Standard and discounted amounts came from separate published tables. No complete matrix import was attempted after checking this subset. Web screenshot requests did not yield usable output. Subsequently downloaded the three official PDFs, rendered them with local Poppler, and visually checked enlarged crops for both directed fare pairs, all five Tamil spellings, and Blue/Green corridor context. The whole network, full matrix and current operational status remain outside this checked subset. Intermediate renders were not added to the app.

Source version: `cmrl-2026-10-retrieved-2026-11-11`. Effective-from remains null rather than treating the directory or page-update date as a fare-effective date. Missing records return unverified with the official table link; no symmetry fallback or interpolation occurs at runtime.

To refresh: check current official publications and superseding policies; independently verify row/column mapping; update `lib/metro/official.ts`, seed snapshot and tests together; record dates/version here. Do not infer current service status from the existence of a fare-table entry. All operational flags are null. If source facts become uncertain, remove the record and keep the official fallback.
