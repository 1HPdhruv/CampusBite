## Fare freshness and date semantics

`lib/metro/fare-policy.ts` checks freshness **when read**, not only when built. Each record requires a validated official source URL, source version, verification date and non-negative independently published standard/discounted amounts. `asOf` is validated as a real YYYY-MM-DD calendar date. Future dates abstain. A record with an unknown effective date is not extrapolated to before its verification date. Explicit effective-from/to bounds are honored.

The **30-day maximum age is MetroSathi's conservative review policy, not a CMRL fare expiry date**. An old record, missing pair, malformed record or unsupported date returns `verified:false`, a stable reason and the official table link with no price. The UI and text guard preserve that abstention. Re-verification requires checking the official publication again; do not refresh the date merely to keep a test green. Discount eligibility/current operations still require operator confirmation.

## ChennaiGTFS quarantine decision

- Source: https://github.com/ungalsoththu/ChennaiGTFS, revision `af0742dba777f9657ed6fda2046d6c2a721d630b`, file `data/cmrl-gtfs.zip`.
- Upstream collection date: **2026-10-04**. It is not the timetable's service-effective date.
- Inspected archive SHA-256: `526deb1bcecbf6328b366a6de13f6cbd77fcb1af4a37d43a344bf49f15983f56`.
- Actual metadata inspection: 254 stop/entrance/platform records, 28 route records, one calendar row ending **2021-12-31**. Agency fare URL points to a 2021 chart. No fare or timetable rows were imported. Feed does not establish current Yellow Line passenger service.
- Exact root code license is MIT. README says compiled data ODbL/PDDL, but also says the mirrored CMRL agency source from CUMTA has no explicit license. Those statements do not establish redistribution rights to the mirrored feed. Runtime promotion is blocked.
- Only derived counts, dates, checksum and rejection categories are committed in `data/chennai-gtfs-inspection.json`. The raw archive and all source rows stayed in the temporary review area and are not bundled or redistributed.

## Importer workflow

`python3 scripts/import-chennai-gtfs.py FEED.zip --manifest REVIEW.json --as-of 2026-11-12 --output REPORT.json` inspects a locally obtained agency-only ZIP, checks its pinned revision/checksum, archive bounds, expected agency and calendar, and writes metadata only. Output uses exclusive-create and cannot overwrite a runtime register. `data/chennai-gtfs-manifest.example.json` deliberately defaults to uncleared data rights and a placeholder checksum.

`--stage-structure` additionally requires explicitly reviewed dataset rights, an evidence URL and reviewer. It validates unique IDs and parent references, namespaces CMRL IDs and stages only source station/stop/route facts with unknown Tamil/operation where absent. It **always excludes fares, schedules and inferred transfers**, even with clear licensing. Staging is never automatic runtime promotion. No network fetch, database access, migration or SQL execution occurs in the importer.

Promotion requires both rights clearance and independent current official verification, schema/reference validation, new source/version/date registration, test review and an explicit runtime update. Never map nearby or similarly named stops into one physical interchange without evidence. Full network/Yellow Line coverage remains incomplete.

## Other upstream data exclusions

OpenMetro's MPL code license is separate from each data-source license. Its network data was not imported. TransitSave's fare values were excluded. Fare Policy Assistant's NOTICE excludes transit-agency corpus text from Apache licensing; none was copied. CMRL-DATASETS describes aggregate ridership, has no reviewed license file and was not imported. Sarvam's missing LICENSE blocks source copying; original Metro speech normalization uses only already checked local names.

## Release audit — 2026-11-12

This is an audit of coverage, not a promotion of additional data. The runtime remains **seven unique stations, two line records (Blue/Green), nine line stops, four directed interchange edges and four directed fare pairs**. It is not a complete Chennai network or fare matrix. Operational flags remain null; route adjacency, travel times and platform transfer details are absent. Tamil names for the two added interchange stations still require review.

Fresh official checks:

- The [fare landing page](https://chennaimetrorail.org/cmrl-fare-table/) explicitly labels its last fare update **09/10/2026**, with page update October 9, 2026. This establishes a publication/update date, not a tariff effective-from date; no runtime verification dates or prices were refreshed without checking individual cells.
- [CMRL PR 66/2026, 10 October](https://chennaimetrorail.org/wp-content/uploads/2026/10/Press-Release-10.10.2026-English.pdf) announces passenger service from **11 October 2026**, Poonamallee Bypass–Vadapalani, 11 elevated stations on Corridor 4 / Yellow Line. [PR 68/2026, 21 October](https://chennaimetrorail.org/wp-content/uploads/2026/10/Press-Release-21.10.2026-English.pdf) confirms this section and a later timetable change. Yellow Line passenger service therefore exists in official current evidence; it is absent from the runtime dataset. The quarantined 4 October GTFS feed predates that announcement and cannot fill the gap.
- [CMRL PR 71/2026, 5 November](https://chennaimetrorail.org/wp-content/uploads/2026/11/Press-Release-05.11.2026-English.pdf) corroborates October passenger operation on Blue, Green and the 11-station Yellow section. This is corridor evidence, not a reconciled complete station/stop graph. Historical [Blue](https://chennaimetrorail.org/phase-one/blue-line/) and [Green](https://chennaimetrorail.org/phase-one/green-line/) pages contain 26 and 17 named entries respectively; their 2024 publication dates and depot entries make a naive operational-station total unsafe.
- Runtime interchange edges cover Alandur and Central between Blue/Green only. Yellow terminates at Vadapalani according to PR 66. The current app has no Yellow stop or verified Green/Yellow transfer connection there; station-name proximity is insufficient to infer walking edges or transfer times.
- [CMRL PR 72/2026, 5 November](https://chennaimetrorail.org/wp-content/uploads/2026/11/Press-Release-05.11.2026-English-1.pdf) has special schedules limited to 5–6 November. These are expired as of this audit and were not adopted as current service times.
- [CMRL PR 32/2026, 21 April](https://chennaimetrorail.org/wp-content/uploads/2026/04/Press-Release-21.04.2026-English.pdf) describes the move to Singara Chennai NCMC from 1 May 2026 and transfer of remaining valid legacy-card value. Historical 2024 recharge instructions in the app remain partial and require policy reconciliation before public passenger guidance. This does not authorize lost-card recovery promises or any real balance transfer.

No bulk dataset, source PDF/image or new fare values were imported. The agency site retains an all-rights-reserved notice; no open dataset redistribution license was established. Linked factual audit observations do not clear a bulk redistribution license. The existing GTFS quarantine, separate upstream-code/data license review and sparse-fare abstention remain in force. Full station coverage, a current operational graph, verified Yellow interchange details, full current fare matrix and current recharge policy are release limitations requiring review.
